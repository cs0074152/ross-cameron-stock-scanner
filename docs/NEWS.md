# 新闻来源核查

点击扫描器里的股票，自动检查来源记录、股票关联和发布时间，并提供原文链接。默认无需 API Key，也没有外部 AI 服务配置。

## 核查了什么

| 检查 | 美股 | 沪深京 A 股 |
| --- | --- | --- |
| 来源记录 | Yahoo Finance 收录的新闻记录 | 巨潮资讯网公司公告记录 |
| 股票关联 | `relatedTickers` 明确包含所选代码 | 股票映射取得公司标识，公告 `secCode` 再次与六位代码核对 |
| 发布时间 | 源提供的 Unix 秒时间；缺失或异常独立标记 | 源提供的公告时间；只有日期时按北京发布日展示 |
| 原文 | 新闻记录中的安全 HTTPS 链接 | 巨潮固定公告文件路径 |
| 范围 | 新闻检索样本，最多十条；不代表该股票全部新闻 | 最近九十天的公告查询，最多十条；不代表所有重大事项 |

近七天计数只包含有效且不晚于当前时间的源发布日期。较早发布、时间未知、未来时间和过期缓存分别说明，不混用“最新”标签。

**找到可追溯来源，不等于报道里的具体说法已经证实。** Yahoo 收录不等于软件独立核验了媒体身份；上市公司公告也不等于对公司主张的独立背书。本轮不解析正文判断事件、数额或事实真假，不判断新闻是否导致股价变化，不合并转载来声称多方独立佐证。原有数值筛选、买点观察和模拟持仓规则保持不变。

## 使用方式

1. 切换市场，在榜单中选择股票。
2. 在图表下方查看“新闻来源核查”，阅读来源及发布日或发布时间。
3. 点标题查看原文；需要时点“重新核查”。

面板跟随榜单选中的代码。TradingView 嵌入图表内部换股不会回传选股状态，因此新闻面板始终明确显示其关联代码。

## 缓存与失败

- 成功结果缓存五分钟；重复查询复用正在进行的任务。手动刷新也有短暂节流。
- 有旧记录时先展示旧缓存，后台重新获取；失败不延长记录的最后成功时间，超过二十四小时不再保留。
- 来源成功但没有匹配项，显示“本次未找到匹配记录”；网络、限流或响应结构错误，显示无法核查。
- “最后尝试”“最后成功获取”“发布时间”含义不同。读取旧缓存不会更新成功时间。
- 单次任务最多六秒，包含等待和读取；响应实际读取最多 2 MB。任务和请求有并发上限，容量不足时稍后重试。
- 页面隐藏时暂停自动请求；新闻查询独立于行情刷新，不阻塞榜单，也不改变模拟持仓。

## 来源与维护

2026-10-08 对公开源站请求进行了实测。Yahoo 与巨潮这里使用的是公开网页端点，未发现稳定的公共 API 契约，接口结构或访问限制可能变化。

- [Yahoo Finance 当前新闻检索端点示例](https://query1.finance.yahoo.com/v1/finance/search?q=AAPL&newsCount=3&quotesCount=1)：返回新闻记录和关联代码；它是本功能的数据来源，不是对报道内容的事实验证。
- [巨潮资讯网](https://www.cninfo.com.cn/)：公司公告来源；网站说明其为深圳证券交易所信息披露官方网站。
- [巨潮公告查询页面脚本](https://static.cninfo.com.cn/new/js/app/data/person-stock-news.js?v=20260710082532)：源站当前使用股票代码及公司标识查询公告。

服务端只访问登记的来源，通过统一出站保护校验每次重定向；客户端不提交任意抓取地址。新闻标题作为普通文本展示，原文链接经过限制，错误内容不会冒充核查成功。公开源可限流、延迟或调整，不能保证持续可用。
